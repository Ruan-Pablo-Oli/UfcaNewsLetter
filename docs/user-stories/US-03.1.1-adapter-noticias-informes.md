# [US-03.1.1] Adaptador de Noticias e Informes

**Parent:** #16: Coletar conteudo automaticamente  
**Tipo:** issue filha de implementacao  
**Prioridade:** P0

## Historia

Como o coletor do sistema, quero transformar as listagens e posts de Noticias e Informes da UFCA em registros extraidos com formato definido, para que a ingestao possa ser persistida e testada.

## Criterios de aceitacao

- [x] Coleta as duas bases `/noticias/` e `/informes/` e segue a paginacao sem depender de JavaScript, RSS ou API REST.
- [x] Extrai de cada post: titulo, URL canonica, corpo, data de publicacao, data de atualizacao quando presente, categoria/breadcrumb e URLs de anexos.
- [x] Emite um registro extraido com formato estavel: `source_url`, `canonical_url`, `title`, `body`, `published_at`, `updated_at`, `attachment_urls` e `content_hash`.
- [x] Deduplica URLs canonicas dentro da coleta e aceita `known_canonical_urls` para que a persistencia de #52 rejeite reprocessamentos entre execucoes.
- [x] Falha de uma pagina ou markup inesperado gera `CollectionError` com URL e motivo, sem descartar silenciosamente os demais registros.
- [x] Testes usam fixtures HTML versionadas para listagem de Noticias, listagem de Informes, post com datas, post sem data, post com anexo, post invalido e paginacao.

## Fora de escopo

Scheduler, migração de modelos, classificação, resumo, moderacao e download do PDF. Esses contratos pertencem a #52, #17, #18 e #27; o download é a US-03.1.2.

## Tarefas

- [x] Criar adaptador BeautifulSoup para listagem e post individual.
- [x] Converter datas e URLs para o formato usado pelo Django.
- [x] Implementar deduplicacao deterministica.
- [x] Registrar erro de parsing com URL e motivo.
- [x] Adicionar fixtures e testes de contrato.

## Integração com a stack

- O modelo persistido é `Conteudo` em [`app/newsletter/models.py`](../../app/newsletter/models.py); a gravação e a constraint de idempotência dependem de #52.
- O adaptador usa `requests`, `beautifulsoup4` e `lxml`, já declarados em [`requirements.txt`](../../requirements.txt).
- O contrato está em `NewsInformeRecord` e os erros em `CollectionError`, ambos em [`app/newsletter/collectors/noticias_informes.py`](../../app/newsletter/collectors/noticias_informes.py).
- Fixtures e testes ficam em [`app/newsletter/tests/`](../../app/newsletter/tests/); o gate é `pytest` conforme [`pyproject.toml`](../../pyproject.toml).
- A alteração de schema e o scheduler continuam sob #52; não criar migration nesta issue.

## Fonte de requisitos

Relatorio de fontes: Noticias/Informes: prioridade P0; URLs-base `https://www.ufca.edu.br/noticias/` e `https://www.ufca.edu.br/informes/`.
